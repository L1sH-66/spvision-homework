|---|---:|---|

| 时间 | 25 | 收到目标到到达耗时 |

**没有公布分段分数、误差阈值、超时上限、是否取多次均值、参考路径冻结方式等细则。下文是推断，不是官方标准。**

## 推断的评测流程与各项的可能口径

1. 拉取指定分支的干净源码，在 Ubuntu 22.04/Humble 上 `colcon build`；**编译失败或启动报错基本意味着前三项全部拿不到**，所以首要风险是“能否一次跑通”。
2. 用你的启动脚本启动，检查起点、地图、仿真器是否原样，有无自动发目标/直接发速度的脚本。
3. RViz 点击一次终点，看双层 BT → 规划 → 控制器的链路，录屏或记录话题。
4. 各项的可能口径：
   - **时间**：最可能读终端里 BT 的到达日志（`[NavStateTrack] Goal reached! ... elapsed=xx s`），或录屏/墙钟从点击到停车。分数多半按同批同学排名或分档给，**是拉开差距最大的一项**。
   - **准确到达**：到达或停车后机器人位置（TF `map→base_link` / 仿真窗口）到 (14.1,14.1) 的距离。原版 0.3 m 判据下所有人都在 0.3 m 左右，只有停得准的人能拿满。
   - **跟踪精度**：录 `/global_path` 和位姿，算点到折线距离。参考路径可能取第一条路径，也可能取当时最新的路径；两种口径都应该小。
   - **报告**：是否讲清楚架构、算法原理、参数取舍、实验数据和局限；图表加分。
   - **可视化与代码管理**：RViz 是否一眼看到代价地图、路径、机器人、目标；`git log` 是否分阶段、信息明确；`.gitignore` 是否排除 build/install/log。
5. 可能当面追问：控制公式、TF 变换、为什么调这些参数、怎样证明优于 PID。

## 本版针对每一项做了什么

| 评分项 | 上一版的情况 | 本版改进 |
|---|---|---|
| 时间 | 1.0 m/s 限速、路径离墙留 30 cm，离线 59.6 s | 辨识仿真器模型后用预测 + MPC，巡航 1.42 m/s（指令不超过 v_max 2.0）；两阶段平滑路径；离线 34.2 s |
| 准确到达 | 稳定判据 0.05 m / 0.5 s，静止误差 2.7 cm | 终点欧氏伺服 + 精确终点 + 不过冲的制动规划，静止误差约 1 cm；判据保持 0.05 m，持续时间 0.5 → 0.3 s |
| 跟踪精度 | 初始路径 RMSE 6.5 cm / 最大 15.5 cm | MPC 横向权重高 + 弯道限速取仿真加速度上限 + 重规划迟滞，平均 1.7 cm / 最大 4.6 cm；各种扰动下最大 ≤ 8.2 cm |

| 加分 | 未宣称 | 代价约束 + 最小曲率两阶段路径平滑；线性 MPC（与同框架 pursuit 对照：标称最大误差 4.6 vs 6.0 cm，dead_time 失配时 7.9 vs 11.4 cm） |

## 仍然存在的风险（如实说明）

- **没有在 Ubuntu 22.04 + Humble 上编译和整链路运行过本版**（开发环境无法安装 ROS）。C++ 核心以 `-Wall -Wextra -Wpedantic -Werror` 编译并通过单测，插件用最小 ROS 替身头文件做过编译检查，但 pluginlib 加载、参数类型、QoS 仍需实测。把仓库推到 GitHub 后 `.github/workflows/ubuntu22.yml` 会在 Humble 容器里编译并跑 `tests/ros_smoke.py`，可以作为免费的整链路检查。
- 离线时间是模拟时间；真实运行有 BT 启动、DDS 延迟和虚拟机卡顿，墙钟会略长。
- 模型参数针对默认小陀螺 3 rad/s；如果评测时底盘模式不同，需要重新辨识 `lag_gain`、稳态表。
- 队友机器人若正好停在走廊中央，会把该走廊整条封死（规划失败 → 停车，不会硬闯）；本题两台队友不在最优路线上。
- 到达判据是自定的（0.05 m / 0.06 m/s / 0.3 s）。如果评委只认原版 0.3 m 判据，本版到达时间会提前约 0.9 s，不会变差。

## 预计答辩问题与回答重点

**为什么要旋转速度？** 路径和位置在 map，仿真器按 base_link 解释速度，而 base_link 的 yaw 是一直在转的云台 yaw；用逆旋转；用 TF 时间戳估计云台角速度，补偿“TF 样本年龄 + 约 17 ms 等下一仿真步”的滞后。

**dead_time 0.24 s 怎么来的？** 阶跃实验测得 0.2 s 纯时延（6 个仿真步），再加里程计/指令各约半个仿真周期的采样等待。

**为什么 lateral_accel = 2.0、brake_decel = 1.2？** 仿真器对速度矢量变化的总加速度限 2 m/s²，向心加速度也算在内；一阶滞后让实际减速度达不到 2，规划用 1.2 才不会冲过终点。

**MPC 的模型是什么，怎么解？** 每轴一阶滞后 `v⁺ = a v + (1−a) w`，位置为其积分；16 步、0.05 s；代价对横向误差权重 300、纵向 4；无约束 QP 用 Cholesky 闭式解，只执行第一步。速度上限在求解后裁剪（不是带约束 QP，这一点要如实说）。

**为什么横向权重远大于纵向？** 跟踪精度与安全取决于横向误差；纵向落后几厘米只影响一点点时间，不该为追参考点而冒切弯的风险。

**平滑会穿墙吗？** 每次移动都检查该点和两侧线段的代价 ≤ 40（离墙约 0.52 m，大于旋转机身外接圆 0.354 m），否则拒绝该移动。

**如何证明优于 PID？** README 5.3：同一框架、同一参数和判据下与 pursuit（预瞄 + PID 型反馈）对照，标称最大误差 6.0 → 4.6 cm，dead_time 失配时 11.4 → 7.9 cm；lag_gain 失配时两者相同；pursuit 快 0.3–2.2 s。结论是 MPC 更准、更稳，不是全面占优，答辩时如实讲。

**还能更快吗？** 自旋底盘对平移指令是压缩响应，指令放到 4 m/s 时实际速度约 1.68 m/s（仍 < v_max 2.0），离线可再快约 2 s。但指令数值会超过仿真器标称最大速度，为避免合规争议没有采用，指令上限保持 2.0。

**为什么 lateral_accel = 2.0、brake_decel = 1.2？** 仿真器对速度矢量变化的总加速度限 2 m/s²，向心加速度也算在内；一阶滞后让实际减速度达不到 2，规划用 1.2 才不会冲过终点。
